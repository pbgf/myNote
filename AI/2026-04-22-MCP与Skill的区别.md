# MCP 与 Skill 的区别

> 会话时间：2026-04-22

---

## 问题一：Skill 和 MCP 的区别

**Skill** 本质上是一段 Markdown 文件，里面写了"如何完成某类任务"的详细指令。当触发某个 skill 时，AI 会读取这个文件，把里面的内容作为上下文（prompt 的一部分）来指导后续行为。它是通过 Read 工具读取文件内容，然后这些内容进入 AI 的上下文窗口。

**MCP（Model Context Protocol）** 是一套协议，用来给 AI 提供外部工具能力。MCP server 注册一批工具（tools），AI 可以通过 `CallMcpTool` 来调用这些工具执行实际操作，比如读写文件、查询数据库、发送消息等。MCP 本身不会把内容"插入到 prompt"，而是在 AI 需要时主动调用，拿到返回结果后再继续推理。

**类比：**
- Skill 像是一本"操作手册"，AI 读完之后知道该怎么做
- MCP 则像是一套"外部 API"，AI 在执行过程中随时可以调用来完成具体动作

两者也可以配合使用——Skill 里的指令可能会告诉 AI "用某个 MCP 工具来完成这一步"，比如 citadel skill 就会指导 AI 调用 `oa-skills citadel` 这个 CLI 工具。

---

## 问题二：注册的 MCP 会被全部加入 prompt 吗？

不是全部加入 prompt，而是**工具列表（schema）**会被注册进来，但具体内容不会直接塞进 prompt。

MCP server 启动后，它暴露的所有工具的**名称和参数描述（schema）**会被加载到 AI 可用的工具列表中。AI 在推理时知道"有哪些工具可以用、每个工具接受什么参数"，但工具的实际执行结果只有在 AI 主动调用时才会出现在上下文里。

**对 prompt 的影响分两部分：**

1. **固定开销**：工具的 schema 描述会占用一定的 token（工具越多，占用越多），每次对话都存在。
2. **动态增加**：每次调用工具后，返回的结果会作为新的内容进入上下文。

**实践建议**：如果注册了很多 MCP server、每个 server 又有大量工具，工具 schema 的 token 消耗会比较可观，建议按需注册，不要把所有 MCP 都开着。

当前环境中只注册了 `sdk-memory` 这一个 MCP server，提供 `memory_write`、`memory_read`、`memory_search`、`memory_list` 四个工具。
